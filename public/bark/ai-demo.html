CRM workflow

Four commands, from a rough request to a sendable email

Claude does the work between the tools. The tools stay the tools — the brief and the copy live in Notion, the design lives in Figma, the template goes to the ESP. What changes is that nobody retypes anything on the way across.

Sendable template

Copy arrives from the feed at send time

The words never move by hand. The same key names a Notion row, a Figma layer and a template slot — so copy review needs no engineer, a new language is a column, and the design cannot quietly disagree with the build.

The steps

Each one ends somewhere a person can look

/campaign-brief

Request → brief and copy

Turns a few lines into a structured brief. Asks only what genuinely blocks; everything else becomes an assumption it labels rather than hides. Writes every word the email will say, in every language, as a table in Notion.

Ends with a campaign record, and copy anyone can edit

/campaign-design

Brief → editable Figma

Real auto-layout and real text layers, each named for its copy key. Raises a review task saying what it would most like overruled — then stops.

Stops here · human approval required

Ends with a design and an open question, waiting

/campaign-build

Approved design → sendable template

Refuses to start unless the design is approved. Reconciles any copy edited on the canvas back into the table, writes the template, builds, runs QA, publishes.

Ends with a preview URL, and the file that goes into the ESP

/campaign-strings

Copy changed → everything follows

The one command to run after editing wording. Pulls from Notion, shows every word that moved, catches the other languages up, rebuilds and re-runs QA.

Ends with the change in the template, in every language
